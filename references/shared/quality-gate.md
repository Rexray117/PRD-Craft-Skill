# PRD 质量门禁（共用层）

每次输出 PRD（概念版对齐稿除外）前**必须**执行。存在未通过项时先补齐再输出，禁止输出带缺口且未标注的文档。

---

## 1. 通用门禁清单（方向 S 与方向 A 均须满足）

| # | 检查项 | 判定标准 | 不通过时的处理 |
| :--- | :--- | :--- | :--- |
| **G1** | 结构完整 | 模板标注「必选」的章节全部存在且非空白；补充说明六节齐备 | 补齐章节 |
| **G2** | 流程含异常分支 | 每个流程至少 1 条异常路径，且使用 Mermaid | 补画分支 |
| **G3** | 占位符双轨合规 | 正文**无** `[待补充：…]`，改用中性表述或省略；补充说明中全部待确认信息均以 `[待补充：{信息项}]` 登记 | 按 `conventions.md` §1 分流改写 |
| **G4** | 无编造内容 | 所有路径、名称、账号、阈值、日期均来自用户输入或已标占位符；中性表述只说明取值来源，不暗示取值 | 回退为中性表述或占位符 |
| **G5** | 待确认清单 | 补充说明 §3 与正文的中性表述 / 省略项一一对应 | 补清单 |
| **G6** | 指标可量化 | 每个指标有定义 + 计算公式 + 目标值，无「高效 / 稳定 / 良好 / 显著提升」 | 重写指标 |
| **G7** | 异常有具体策略 | 每条异常有明确处理方式，非「人工处理」「稍后重试」 | 补具体策略 |
| **G8** | 语言一致 | 全篇同一语言，专有名词除外 | 统一语言 |
| **G9** | **正文零杂项** | 正文不含版本号、日期、作者、名词解释、需求背景、痛点、目标用户、成功标准、待确认清单、篇幅说明、压缩说明、配套索引、元信息行 | 移入补充说明对应节 |
| **G10** | **成对交付** | 正文与补充说明同目录同时产出；补充说明 §3.3「正文留空位置对照」覆盖正文每一处双轨制处理 | 补齐缺失文档或对照项 |

### G9 的具体检查项（逐项核对）

| 序 | 检查内容 | 出现即违规的示例 |
| :--- | :--- | :--- |
| 1 | 元信息行 | `> 版本：v1.0 ｜ 日期：2026-01-01 ｜ 作者：某某` |
| 2 | 版本号 / 基线版本 | `v2.0`、`基线 v1.0` |
| 3 | 日期 / 作者 | 任何 `YYYY-MM-DD` 与署名 |
| 4 | 名词解释表 | 「名词解释」「术语表」章节 |
| 5 | 角色与读者表 | 「角色与读者」「读者指引」章节 |
| 6 | 需求背景 / 痛点 | 「业务现状」「痛点」「触发因素」章节 |
| 7 | 目标用户 | 「目标用户」「用户画像」「使用角色」章节 |
| 8 | 需求目标 / 成功标准 | 「需求目标」「成功标准」「北极星指标」章节 |
| 9 | 待确认清单 | 「待确认清单」「待定事项」章节 |
| 10 | 篇幅 / 压缩说明 | 「篇幅对照」「本次压缩说明」 |
| 11 | 配套索引 | 「配套文档索引」「参考资料」章节 |
| 12 | 未决标记 | `[待补充：…]`、`待定`、`TBD`、`TODO`、`—` 作留空标记 |

> 例外：正文允许保留指向补充说明的**需求指针**（如「XX 规则见《补充说明文档》」），不视为杂项。

---

## 2. 门禁执行结果

(1) **全部通过** → 在对话中输出一句「质量门禁 10 项已全部通过。」

(2) **存在不通过** → 先补齐内容，再**重新执行全量门禁**，不跳过任何一项。

(3) 门禁结果**禁止**作为独立章节写进 PRD 文档。

(4) 通用门禁 G1–G10 可按 `scripts/validate.py` 的自动扫描结果辅助核对；脚本报错时先修复再交付。

私有门禁**禁止复制**本文件的 10 个条目，只写通用基线之外的增量项。
