# 异常处理与降级规范（共用层）

方向 S 与方向 A 共用的异常分类基线与降级策略表结构。各特化层在正文中**引用本文件**，不重复定义分类与表头。

---

## 1. 通用异常分类（穷举基线）

写异常处理时，以下 5 类必须**逐类检查是否适用**，不适用则注明「本场景不适用，原因：[原因]」，禁止留空表。

| 类别 | 典型场景 | 处理策略要求 |
| :--- | :--- | :--- |
| **输入异常** | 参数缺失、格式错误、超长、非法字符 | 前置拦截 + 明确错误提示，禁止静默失败 |
| **依赖异常** | 接口超时、下游不可用、限流、返回脏数据 | 重试 → 降级 → 熔断；写明重试次数、退避策略与降级返回值 |
| **数据异常** | 空结果、数据量超预期、数据过期、口径缺失 | 空状态展示 / 数据兜底 / 告警 |
| **权限异常** | 未登录、越权访问、令牌过期、角色不符 | 拦截 + 引导登录或申请权限 |
| **环境异常** | 断网、资源不足、并发超限、时钟漂移 | 本地缓存 / 排队 / 友好提示 |

方向 A 额外需覆盖以下 4 类（属「依赖异常」与「数据异常」的细分，逐项检查）：

| 类别 | 典型场景 | 处理策略要求 |
| :--- | :--- | :--- |
| **模型不可用** | 端点超时、服务端错误、配额耗尽 | 退避重试 → 降级为规则模板输出 → 不阻断主链路 |
| **数据不足** | 窗口内有效数据点不足 | 标记数据不足，不消耗配额，不产出低质量结论 |
| **输出不合规** | 命中安全策略、脱敏环节异常、必填字段缺失 | 阻断输出 / 重试一次要求严格结构化；保留原始返回备查 |
| **幂等冲突** | 未恢复期间重复命中、重复触发 | 只更新既有记录的时长与快照，不新增记录 |

## 2. 降级策略表（必写）

| 异常场景 | 触发条件 | 降级策略 | 用户可见反馈 | 恢复方式 |
| :--- | :--- | :--- | :--- | :--- |
| [待补充：异常场景] | [待补充：触发条件] | [待补充：降级策略] | [待补充：提示文案] | [待补充：恢复条件] |

### 要求

- 降级策略必须写**具体动作**，禁止「人工处理」「稍后重试」「系统自动处理」等无信息量表述
- 「用户可见反馈」必须是**可直接使用的文案原文**
- 「恢复方式」需说明是自动恢复还是需人工介入
- 方向 A 需额外确认：本能力失败是否阻断其他能力、降级输出是否标注降级标记、降级是否留痕

## 3. 边界场景穷举清单

为每个功能 / 能力逐项检查下表，确认已覆盖或已注明不适用。

| 场景 | 检查内容 |
| :--- | :--- |
| 空状态 | 无数据、首次使用、无权限时看到什么 |
| 加载中 | 耗时操作的进度反馈、可否离开页面 |
| 极值数据 | 数据量为 0 / 1 / 超预期时的表现 |
| 并发 | 同一对象被重复触发、多人同时编辑 |
| 重复触发 | 同一请求重复提交、定时任务重入 |
| 中断恢复 | 用户中途离开、网络中断后重入 |
| 权限变化 | 会话中权限被回收 |
| 时区 / 时间 | 跨日、跨时区、夏令时、时钟回拨 |
| 数据过期 | 数据源延迟、缓存陈旧、补传数据 |
| 终态后操作 | 已关闭、已归档、已失效对象仍被操作 |
