# 能力规约与输出规范（方向 A · Agent 类系统 私有层）

本文件对应落地版 PRD 第四章「能力规约」与第六章「依赖、数据与接口」的细则，是方向 A 相对方向 S 的核心差异所在。

占位符与语言规则遵循 `../shared/conventions.md`，不在本文件重复。

---

## 1. 能力划分原则

一个能力 = 一个可独立描述、可独立验收的任务闭环。

| 划分问题 | 判定 |
| :--- | :--- |
| 粒度过细？ | 多个能力共享同一触发源、同一套规则、同一类输出 → 合并 |
| 粒度过粗？ | 一个能力下出现两套互不相干的决策规则或两种互不相关的输出 → 拆分 |
| 推荐粒度 | 一个能力对应「一类触发 → 一套规则 → 一种输出」 |

能力数 ≥ 5 时，建议在第四章开头补一张「能力 × 章节速查表」，便于测试逐能力核对。

## 2. 场景描述（对应 4.x.1）

篇幅 100–200 字，必须包含三要素：

| 要素 | 要求 |
| :--- | :--- |
| **问题** | 现状下会发生什么，写明可观测的事实 |
| **Agent 角色** | 该能力中 Agent 承担什么，写明边界 |
| **核心价值** | 做完后行为发生什么可观测变化 |

**禁止**出现「高效」「便捷」「智能」等无度量意义的形容词。

## 4. 人机边界（对应 4.x.5）

Agent 类系统的核心安全设计。**逐项标注**每个动作的执行方式，三类缺一不可。

| 动作 | 执行方式 | 依据 | 备注 |
| :--- | :--- | :--- | :--- |
| 读数据 / 判定 / 生成内容 | **自动执行** | [规则章节] | 无需人工介入 |
| 对外通知 / 推送 | **自动执行** | [规则章节] | 脱敏后发出 |
| 产生实际影响的动作 | **需人工确认** | [规则章节] | 恒为需确认，任何版本不得放开 |
| 命令下发 / 配置变更 / 写操作 | **永久禁止** | [硬约束编号] | 如需放开须先修订硬约束，单独走变更评审 |

## 5. 输出规范（对应 4.x.6）

Agent 输出具有不确定性，必须做**双向约束**：既规定必须出现什么，也规定禁止出现什么。**两者缺一不可。**

### 5.1 必须包含的内容

| 字段 / 信息项 | 类型 | 说明 |
| :--- | :--- | :--- |
| [字段名] | 字符串 / 数字 / 对象 / 数组 | [必须包含的原因与内容要求] |

### 5.2 禁止出现的内容（至少覆盖以下 5 类）

| 禁止项 | 类型 | 说明 |
| :--- | :--- | :--- |
| 敏感信息 | 内容 | 密钥、令牌、证书、完整内网地址等，禁止未脱敏输出 |
| 技术细节 | 内容 | 内部堆栈、SQL、系统内部实现细节 |
| 破坏性指令 | 内容 | 禁止输出可直接执行的破坏性命令 |
| 绝对化承诺 | 措辞 | 禁止「已自动处理」「已修复」「一定」「保证」等表述 |
| 无来源推测断言 | 内容 | 每条结论须可追溯至库内数据 |
